# cross-lineage-review —— 换谱系对抗性评审

**为什么**：上下文被任务喂过的模型，再读一遍只会再次确认自己是对的。偏见来自整套装置（Harness + 模型 + 上下文），所以要换谱系、给干净上下文。

## 第一步：打包（指针法，不贴全文）

把「评审对象 + 上下文 + 提示词」写成一个自足的临时文件，放过程材料区：`tmp/review-pkg-YYYYMMDD.md`（tmp/ 已被 .gitignore 忽略）。包里写清四样：

1. **要读什么**：文件路径 + 行号范围，一行一个指针；
2. **上下文**：相关 PRD / 约束 / 已知限制文件的路径；
3. **排除项**：哪些明确不用看（一条不看的抵十条要看的）；
4. **评审提示词**（写死）：

   > 请扮演最挑剔的评审者，只查事实、逻辑、漏洞与自相矛盾，不评风格。逐条输出：哪个文件、哪一行、为什么是问题、定级 P0/P1/P2/P3。没有就明确说「没有」，不许拿「部分相关」凑版面。800 字以内。

   对方读不到本地文件时，把涉及的内容片段复制进包里（保持行号指针以便回改）。

## 第二步：派出去（优先与本会话不同公司/谱系的模型）

```bash
codex exec -m <模型名> "按 tmp/review-pkg-xxx.md 评审"     # 或对应 CLI 的非交互参数
```

或者把包内容原样交给另一家旗舰对话框（Kimi / GLM / DeepSeek / GPT），提示词一字不改。

## 第三步：分级修复

- **P0、P1、P2 修到零；P3 酌情。**
- 凡属风格的「问题」一律不升级——保护风格。
- 本项目额外一条驳回线：凡建议削弱「AI 结果可编辑 / 人工确认闸门 / 不虚构数字」三条底线的意见，一律驳回——那是产品身份，不是 bug。
- 评审结论（采纳/驳回 + 理由）落盘 `docs/review/` 或 devlog；「哪一条是原模型完全没看见的」单独记一笔，那是换谱系的价值实证。

## 降级方案

- 本机没装第二家 harness：新开一个**无上下文**会话（或无状态子代理），把 `tmp/review-pkg-xxx.md` 完整喂进去。效果弱一档（同谱系），汇报时必须注明「同谱系评审」。
- 冒烟先行：第一次用某个外部模型时，先拿一小段已知有问题的材料试一次，确认它真的会挑错、真的按格式输出，再派正式评审。

## 去哪装

- Codex CLI：https://developers.openai.com/codex/cli ；Kimi CLI：https://github.com/MoonshotAI/kimi-cli （安装方式一律以各自官网为准）。
- 装不上按 CLAUDE.md 意外矩阵走镜像 / 原样明报，不静默换方案。
