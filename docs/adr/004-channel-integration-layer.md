# ADR-004: 消息渠道接入层——飞书/钉钉/企业微信入站 webhook

**状态**: Accepted
**日期**: 2026-09-06
**决策者**: 本人（口径）;实现细节 AI

## 背景

产品愿景是「Message != Case」: 居民反馈从各种渠道进来,经 AI 整理成草稿,由人确认成事项。当前唯一入口是工作台手工粘贴,居民消息所在的即时通讯平台(飞书/钉钉/企业微信群)无法自动进入系统。个人微信群**没有官方机器人接口**,可行路径是飞书/钉钉开放平台自建应用与企业微信接收消息回调。

初赛演示在即(2026-09-06),动演示主链路风险不可接受;且接入凭据(各平台 App ID/Secret)按纪律归本人办理,AI 不代办。

## 决策

新增**自包含的入站接入层**,对演示链路零改动:

1. 统一入口 `POST|GET /api/integrations/[platform]/webhook`(platform = feishu | dingtalk | wecom) + `GET /api/integrations/status`(只报就绪态与缺失变量名,不回读密钥值)。
2. 每平台一个纯函数适配器(`src/lib/integrations/`): 按官方公开文档实现签名校验(钉钉 HMAC-SHA256、飞书 token 比对、企微 msg_signature=SHA1)、加密载荷解密(飞书/企微 AES-256-CBC 约定)、事件归一化为 `{externalMessageId, text, senderName}`。
3. **未配置凭据 = 如实 503** `INTEGRATION_NOT_CONFIGURED`(列出缺失变量名),不冒充可用——与设置页「敬请期待」同一口径纪律。
4. 建件复用 `/api/intakes` 现有创建契约(同一份 zod 校验、幂等键 replay/P2002 语义),幂等键 = `${platform}:${externalMessageId}` → 平台重推天然去重;`sourceType` 记录平台名留溯源。
5. 非文本消息、机器人自身消息等**明确 ignore 并返回原因**,不静默吞掉。

## 后果

正面:
- 演示口径可以如实讲「接入层已就绪,凭据接入即点亮」;凭据到位后只需配 env + 一次真实消息冒烟。
- 契约测试(19 项,对称加解密 + 签名正反例 + 路由接线)全部离线运行,CI 无外部依赖。
- 复用建件契约,Intake 侧零改动。

负面/边界(必须如实声明):
- **未与真实平台联调**: 契约测试证明实现符合公开文档的算法约定,不等于真实平台回调可用;凭据接入后须先跑一次真实消息冒烟再宣称可用。
- 仅入站文本消息;图片/语音与**推送回群(outbound)未实现**,个人微信不做。
- 钉钉回调载荷存在多种模式差异,适配器按文档主流格式实现,联调时可能需要小改。

## 替代方案

- 立即真实接通一个平台: 需要凭据且动演示链路,演示前夜风险最高,否决。
- 只写文档不做代码: 接入层本身自包含且未配置时零行为,风险可控,故采用实现。
- 独立 worker/队列处理回调: 当前量级(SQLite 单机演示)不需要,保持 Modular Monolith(ADR-001)。
