# exp001：待办与回访的六条合成记录检查

日期：2026-10-10。性质：合成技术/展示检查；没有真人参与者、模型模拟经办人或外部机构回执。

## 假设与输入

设计假设：已有负责人、行动时间和回访字段足以在原服务页找到下一动作，暂不需要迁移 schema。检查逻辑与表达能否成立；是否减少遗漏或录入负担仍未知。

浏览器时间固定为 2026-10-10 10:00（Asia/Shanghai），使用 E2E 专库与强制 Mock。以下六条通过真实本地 API 创建，姓名/对象/反馈均为合成。

| 输入 | 有效时间与负责人 | 预期初始展示 |
| --- | --- | --- |
| 到期就业联系 | 10-10 09:00，合成甲 | 待联系 / 已到联系时间 |
| 转介发出待接收 | 10-10 09:00，合成甲 | 待联系 / 转介待接收 / 结果未确认 |
| 转介退回待补充 | 回访 10-11 09:00，旧计划 10-10 09:00，合成乙 | 未来安排 / 退回待补充 |
| 本次探访确认、后续联系 | 回访 10-17 09:00，旧计划 10-10 09:00，合成乙 | 未来安排 / 本次已确认但尚未收尾 |
| 联系未接通 | 回访 10-10 12:00，合成甲 | 待联系 / 今日稍后 / 结果未确认，保留原联系记录 |
| 已收尾探访历史 | RESOLVED，回访 10-18 09:00，合成乙 | 仅全部事项 / 历史联系安排；可人工开启新周期 |

同一 SYN-P01 的就业事项、同一 SYN-P02 的两条探访记录均分别展示。单位测试另覆盖缺失/异常时间、三个收尾状态、午夜边界和重新开启。

## 做法与观察

运行纯函数单测和 Playwright，核对初始计数为待联系 3、未来安排 2、全部 6；按合成乙筛选为 0 / 2 / 3。进入历史详情保留收尾状态与新周期入口。仅刷新列表不会覆盖尚未保存的目标编辑，整页重载按持久记录恢复。

将未接通事项改约为 10-12 09:00 后，计数变为 2 / 3 / 6，结果仍 UNKNOWN；历史未被自动重新打开，同一对象的其他需求未合并。390×844 浏览器无横向溢出，并检查卡片内容没有被可滚动列表压缩。最终结果及执行中的问题见 [实现日志](../../devlog/LIVELIHOOD_FOLLOW_UP_2026-10-10.md)。

检查代码：[展示规则测试](../../../apps/web/src/lib/__tests__/service-follow-up.test.ts)、[真实 API/页面检查](../../../apps/web/tests/e2e/service-follow-up.spec.ts)。

## 取舍影响与限制

这次支持继续在现有栈内保留小型人工待办；没有证明该方向优于减少重复填表或来源整理。已完成探访的未来约定保留在历史，后续周期仍需人主动建立，这种工作方式是否容易遗漏需要实际工作人员核对。异常服务快照仍由既有 API 拒绝读取，日期待核对的防御展示不会绕过快照校验。
