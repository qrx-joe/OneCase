# exp002：待办与回访的六条合成任务复核

日期：2026-10-10。性质：AI 依据实际页面/代码进行任务复核，加纯函数与浏览器回归。真人自查、一线走查、理解时间和满意度均未执行。

## 问题与方法

检查已有六条合成记录能否在页面上提供“对象、内部负责人、联系安排、下一动作”的明确线索，尤其是已收尾探访的后续约定。不能据此声称人已经理解或减少漏访。

采用 exp001 的固定浏览器时间 2026-10-10 10:00（Asia/Shanghai）和 E2E 专库；为各合成计划填写具体下一行动，保留转介/结果与历史状态。测试寻找实际卡片文字、日期与入口，并操作新周期草稿和保存/重载。合成场景是测试输入，不是模型生成的经办人反馈。

## 发现与修正

- F01，设计风险：初版待联系/未来安排均隐藏已收尾事项，后续约定只有历史入口。增加“待接续”筛选，不改变旧事项状态，也不把已完成事项计作未完成服务。
- F02，实际日期缺陷：原约定 10-28 09:00，点击新周期草稿却变为 10-11 10:00。修正为预填原 followUpAt；人仍可调整日期并确认保存，未保存时不消除接续提示。
- F03，表达改进：普通历史卡片的行动改称“上轮行动”；待接续卡片显示核对本轮意愿及安排、人工开启新周期，避免把旧行动当新的任务。

接续提示仅依据 RESOLVED/CLOSED、明确 followUpAt 和是否存在有效 previousCaseId 周期关联；取消事项和只有旧计划日期的历史不提示。关联还核对同对象/同服务，负责人不同不阻止接续，时间接近或同对象但无关联不消除提示。已有后续事项不等于其服务成功；其 UNKNOWN 和人工核实仍独立保留。
