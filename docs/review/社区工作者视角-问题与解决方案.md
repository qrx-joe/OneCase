# OneCase 审查：社区工作人员视角的问题与解决方案

- **版本**: v2（2026-09-01，按[复核意见](./社区工作者视角审查-复核意见.md)修订：修正 4 处事实描述、收回 1 条高风险方案、重排路线图；v1 与复核的对照结论见文末附录）
- **审查视角**: 一线社区工作人员（社工/网格员）能否真实使用
- **审查方式**: 阅读仓库代码与文档（README、PRD、DEMO_SCRIPT、核心页面/Domain/Schema），模拟一线使用场景
- **总结论**: 对"我"的工作方式理解是对的，信任设计优于同类产品；但按现状**用不上、不敢用、用了也未必省时间**——它优化的是记录环节，而记录是一线工作里最轻的一环。

> **证据边界说明**: 本文基于"代码检查 + 合成数据演示"两层证据。凡涉及"手写台账 30 秒""一多半诉求是调解咨询类""比手写快"等量化判断，均为**待验证假设**，需经阶段 0 访谈与脱敏可用性测试证实，不构成已验证结论。

## 〇、值得保留的优点（解决任何问题时不能破坏）

| # | 优点 | 体现 |
|---|---|---|
| A1 | AI 不替人做主 | `Message != Case / AI Draft != Business Fact`（README）；建案/关联/关闭全由人工确认，查重只给 Top3 候选并标注 Hard Negative，不自动合并 |
| A2 | 数据不丢 | AI 失败保留原文、可重试不重复建档、可转手动建 Case、刷新可恢复 |
| A3 | 留痕与防呆 | 状态机屏蔽非法操作、Timeline 审计、乐观锁防互相覆盖 |
| A4 | 不吹牛 | Demo 数据明确标注、Mock 明确说"不能识别图片"、README 直接写"请勿录入真实居民隐私" |

> **约束**: 下文所有解决方案都必须在保留 A1–A4 的前提下实施。特别地：**未校准的重复候选不得预选"关联"**（v1 方案已收回，见 P4），任何阶段都不自动执行关联或合并。

## 一、阻断级问题：现在根本用不了

### P1. 入口错位：产品不在工作现场

**问题**
- 居民消息在微信里，产品是网页；社工在楼栋间、在现场，用的是手机。
- 移动端现状（v2 修正）：`globals.css` 已有 1024px/768px 响应式规则，窄屏变单列、侧栏隐藏——**已有基础响应式，但手机端无替代导航（底部 Tab）、表格未降级为卡片、触控尺寸/键盘遮挡/真机流程未验证，不能视为移动端可用**。
- 操作路径"微信复制 → 打开网站 → 粘贴 → 等 AI → 逐条确认"可能比"微信里直接回复 + 记备忘"更慢（待验证）。

**解决方案（分步，先验证再投入）**
1. **手机端关键路径补齐**：底部导航、输入/Review/详情三页移动可操作、表格卡片化。这是最小闭环，优先于一切分享集成。
2. **一步进入（先做真机 Spike 再定）**：Web Share Target 仅在 PWA 安装并被系统注册后可用，浏览器/OS 支持不一致（公开资料主要确认 Android WebAPK/ChromeOS）；iOS 剪贴板读取受 HTTPS、用户激活和显式粘贴限制，**不能承诺"微信长按即可转入"或"无感粘贴"**。先用目标设备 + 微信版本做安装路径 Spike，验证通过再建设。
3. **企微应用放试点期**：需目标社区有企微组织，拿到试点社区后再做。

### P2. 不敢录真实数据

**问题**
- 无生产级认证与访问控制；分析时居民敏感内容发送给配置的模型服务——政务场景数据出域是红线。
- README"请勿录入真实居民隐私"即当前系统的真实使用边界。

**解决方案（v2 修正：认证是数据模型级缺口，不只是登录页）**
- Schema 现状：Case 只有 `assigneeId` 无 `createdById`，Intake 无创建人字段，`CaseAction.userId` 可空，三个页面均提交硬编码 `'demo-user'`。因此需要：
  1. **数据模型补齐**：创建人/负责人/操作人字段，服务端注入身份，不信任前端提交的 userId；
  2. **最小认证**：服务端认证与 session、组织与对象级授权、访问审计；
  3. **数据治理**：数据最小化、留存/删除/脱敏导出规则、模型输入与日志和附件的完整数据边界、密钥管理；
  4. **部署**：可私有化或合规端点的模型、PostgreSQL + 对象存储；
  5. 与试点单位书面确认部署、授权和数据处理责任。
- 以上是"真实数据影子试点"的前置门票，全部完成前系统仍禁止录入真实隐私。

### P3. 会变成"第四本账"（双重录入）

**问题**
- 不替代 12345、不接网格化平台（PRD 非目标），同一件事可能要录两遍；没有导出/打印，迎检材料回头手抄。

**解决方案（v2 收敛：先做一个确定格式的闭环，不承诺兼容所有台账）**
1. **导出模板由真实样表决定**：先收集目标社区的脱敏台账样表/迎检材料格式，再定义字段，不凭推测设计。
2. **Excel 导入闭环**：含字段映射、地点别名、类别映射、重复处理、无效状态、时间格式、导入预览、错误报告和可回滚——不只是"灌库"。
3. **打印视图 + 月报导出**，验证"无需二次手工整理"。
4. 长期有真实对接诉求后，再评估向上级平台的单向上报 API。

## 二、价值级问题：用了也未必省时间

### P4. 确认负担可能超过整理负担

**问题**
- 一条普通消息走全流程要看草稿、核字段、看缺失信息、比对 3 个候选、逐条决策；改标题/地点后候选还会"过期重查"。
- 北极星指标是"缩短整理时间"，但真实基线一次没测过。

**解决方案（v2 修订：收回"高分候选默认关联"）**
1. ~~高分候选默认"关联"~~ **收回**：当前评分自标"未校准"，预选关联会产生自动化偏见，违背 A1。改为：
   - 无候选时，可测试默认"创建新事项"；
   - 有候选时，保持人工主动选择；
   - 仅在真实 Gold Dataset 上完成 Precision/Recall/Hard Negative/阈值校准后，才测试推荐预选；任何阶段不自动关联。
2. **"跳过"改成业务出口**（v2 修正：REJECTED 底层能力已存在且留痕，缺的是语义）：已答复无需跟进 / 仅记录不形成事项 / 无效或重复信息 / 暂不受理并记录原因。
3. **字段级简化**：缺失信息折叠展示。
4. **测量口径**（阶段 0 用）：不只测页面操作时间，还测微信/电话到登记的切换时间、补缺时间、查重时间、催办回访办结材料时间、误建漏建错关联的返工时间。

### P5. 语音缺位

**问题**
- 老人主要发语音、打电话；入口禁用，提示"自行转写后粘贴"。

**解决方案（v2 降级：从 P0 改为证据驱动）**
- 语音转写涉及音频上传、模型出域、识别纠错、方言适配、成本与留存风险，不宜未验证即列 P0。
- 改为：**阶段 0 访谈必须回答的问题之一**——"语音/电话是否是目标社区最高频且最费时的输入？"证实后，再在 ASR 方案（第三方/私有化/人工辅助转写）中按数据边界选择。

### P6. 查重冷启动无用 + 启发式接不住中文地点

**问题**
- 无历史导入，"多 Intake → 1 Case"价值需数月积累；当前为未校准启发式（embedding 未接），"3栋2单元/三号楼二单元/我们楼里"类表达难匹配；演示中 1.00 高分来自 seed 编排，不代表真实效果。

**解决方案**
1. **历史导入**（同 P3，含完整清洗与回滚机制）。
2. **地点字典 + 别名表**：社区专属（栋/单元/公共区域），录入与 AI 提取时归一化。
3. **按原计划接 embedding + Gold Dataset 校准**：仍只做候选排序，不自动合并。

## 三、细节级问题：台账字段与真实工作对不上

### P7. Case 缺关键台账字段

**问题**（schema.prisma Case 模型）
- 缺：居民联系方式、责任单位、办结时限、处理前后照片。

**解决方案（v2 修订：字段设计等真实样表；Demo 阶段保留遮挡提示）**
1. 先收集真实脱敏台账样表，再划分字段归属：哪些属 Case、哪些属居民/联系人、哪些属办理动作与回访记录、哪些属可配置字典、哪些敏感字段需独立权限与留存策略。
2. **"请先遮挡姓名电话"提示在合规能力完成前不删除**（v1 建议立即替换，已收回——否则扩大当前隐私风险）。试点阶段将联系方式设计为独立受控字段（加密、明确角色/目的/留存期限/删除方式）后再替换提示。

### P8. 类别只有 5 个，覆盖不了真实诉求

**问题**
- 现有 5 类；真实社区大量诉求（调解/咨询/救助/物业矛盾等，**比例待验证**）落不进任何类。

**解决方案**
- 类别字典以目标社区真实字典为准补全 + 可配置管理页（类别本就存于 `Category` 表）。同样不凭推测定型。

### P9. 没有催办，事项会沉底

**问题**（v2 修正：不是"没有搜索"）
- "全部事项"页已有本地搜索（标题/编号/地点/类别）；失效的是 `AppLayout` 顶栏全局搜索框（值未传给任何页面）和通知铃铛（无响应）——死 UI 比没有更伤信任。
- 无超时/逾期预警，"等物业修灯"卡两周无提醒。

**解决方案**
1. 通知铃铛接真实数据：dueDate 逾期、WAITING/OPEN 超期的 Case 计数，点开为过滤列表；首页第一屏"今日逾期/待催办"。
2. 顶栏搜索：删除，或跳转并把查询传给事项页已有搜索——**不需要新建服务端搜索 API**。

### P10. 术语是工程师语言

**问题**
- 侧边栏"新建 Intake"、处理步骤"AI 事件化"、详情页责任人显示数据库 ID"用户 cXyZ…"（cases/[id]/page.tsx:281）、状态"等待外部"。

**解决方案**
- 中文化：居民来件 / AI 草拟 / 等待物业/街道 / 真实姓名或"待分派"。低风险、可快速验证，适合放入阶段 1。

## 四、验证与实施路线（v2 重排）

> v1 的问题：阶段 1 要求"5 位社工真实使用两周"，阶段 2 才建登录/加密/私有化——两者矛盾（合规建设前禁止录真实数据）。v2 区分**脱敏可用性测试**与**授权真实影子试点**，并新增阶段 0。

| 阶段 | 内容 | 覆盖问题 | 验证门槛 |
|---|---|---|---|
| **0 验证真实问题（不扩系统）** | 访谈/观察 5 位一线人员；用脱敏样本绘制"接收—登记—处理—催办—回访—办结—迎检"全流程并计时；收集脱敏台账样表、类别字典、地点表达（含语音占比）；明确试点授权与部署边界 | 为全部问题建立基线 | 能用证据回答"最重的是录入、查重、催办、回访还是材料整理" |
| **1 最小手机可用闭环（合成/脱敏材料）** | 手机端导航与三页可操作、术语中文化、删/接死按钮、"跳过"改业务出口、无候选时默认"创建"；记录任务时间、返回修改次数、放弃率 | P1(移动优先) P4 P9 P10 | 关键任务时间与错误率优于现有原型，社工能独立理解操作 |
| **2 台账兼容价值** | 真实样表确认的 Excel 导入（预览/错误报告/回滚）+ 迎检格式导出 + 打印视图 + 初版地点/类别映射 | P3 P6(导入) P7(字段) P8 | 同批数据无需二次手工整理，导出可直接或少量修改后用于现有流程 |
| **3 真实试点门票** | 认证与 session、组织/对象级授权、创建人/负责人/操作人模型、服务端身份注入、访问审计、敏感数据/附件/日志治理、留存删除脱敏、合规模型与存储部署 | P2 | 通过试点单位数据与安全审查，方可开始真实数据影子运行 |
| **4 基于真实数据校准 AI 与自动化** | 地点字典、社区类别字典、历史清洗、Duplicate Gold Dataset、embedding 与阈值校准、催办规则、语音转写、企微/上级集成——逐项单独验证 | P1(企微/分享) P5 P6(校准) P9(深化) | 每项能力有净收益证据后才投入下一项 |

**一句话总结**: 先用脱敏材料搞清楚真实工作里最重的环节（阶段 0），再做手机上能用的最小闭环（阶段 1）和台账进出闭环（阶段 2）；价值被证实后，补齐真实试点的合规门票（阶段 3），最后才用真实数据校准 AI 能力（阶段 4）。

## 五、证据分层（后续所有结论须注明来源层级）

| 证据等级 | 可以证明 | 不能证明 |
|---|---|---|
| 代码检查 | 某字段、页面或逻辑存在 | 一线人员会使用、业务有效 |
| 本地测试 | 逻辑按测试样例运行 | 真实设备/数据/组织适用 |
| 合成数据演示 | 产品概念可表达 | 查重准确率、效率提升、生产安全 |
| 脱敏可用性测试 | 用户能否理解和完成任务 | 真实业务持续采用、合规就绪 |
| 授权影子试点 | 真实流程中的效率、错误和留存 | 大规模部署效果 |
| 持续生产使用 | 特定组织中的实际价值 | 自动推广到其他社区仍有效 |

## 附录：v1 → v2 修订记录（与复核意见的对照）

**采纳的事实修正（经代码复核属实）**
1. 移动端：已有 1024/768 响应式规则（globals.css:1519/1536），改为"手机端导航缺失、未移动优先设计"。
2. 认证：Case 无 `createdById`、Intake 无创建人、页面提交硬编码 `demo-user`，"只缺登录页"说法撤回。
3. 搜索：cases/page.tsx 已有本地搜索，死的仅是顶栏全局搜索框，最小处理不需要新服务端 API。
4. 轻路径：Review 已有 REJECTED/"跳过"且留痕，改为补业务语义而非补能力。

**采纳的方案风险修正**
5. 收回"高分候选（score>0.85）默认关联"——未校准评分 + 预选 = 自动化偏见，违背 A1；仅保留"无候选默认创建"的测试。
6. 影子测试与合规建设的顺序矛盾——拆分为"脱敏可用性测试"（阶段 1）与"授权影子试点"（阶段 3 之后）。
7. PWA 分享路径降格为"先真机 Spike"；iOS 无感剪贴板读取不承诺。
8. "删除隐私遮挡提示"暂缓至合规能力完成后。
9. 阶段 1 范围缩减（移出 ASR、企微、私有化、数据库迁移），避免失败无法归因。
10. "30 秒""一多半诉求"等量化说法标注为待验证假设；新增证据分层表。

**保留的差异（1 处）**
11. 语音缺位不无限期搁置：列为阶段 0 访谈的必答题，证实即进阶段 4 首位，而非泛化的"证据到位再说"。
