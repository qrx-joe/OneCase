# OneCase 实际并发修复 · 2026-10-07

本轮针对实际 API + SQLite 建立复现并修复；只使用合成数据，无真实模型外呼。本文先记录并发修复阶段，末尾记录随后获授权的构建修复与 CI 核验流程。保留工作区已有调研、backlog 和架构文档改动；网站尚未发布。

## 复现与修复

1. **过期状态请求误报 422。** 四个独立 Node/Prisma 进程同时提交相同版本，胜者改变状态后，其他请求先走状态机校验，被当作非法迁移。改为先比较版本，再校验当前版本的迁移；仍保留写入的 `id + version` 条件更新。回归验证一个 200、三个 409，版本只加一，审计只有一条。非整数/负数版本返回 400。
2. **按行数编号导致持续 500。** 构造合法历史编号并删除较早记录后，`count()+1` 再次分配现存编号，四个并发新建请求全部撞唯一约束。新增持久 `CaseNumberSequence`，用单条 SQLite UPSERT + RETURNING 原子分配，与 Case/来源/审计同事务提交。兼容已有纯数字 `CASE-N` 编号，初始水位至少 1000；已有编号不改写。之后导入更大编号时分配器会上调水位。已分配事项删除后不退号，失败事务回滚分配。
3. **确认返回结果在回滚后泄漏。** 先创建/关联/处置一个草稿，再让后续决策失败，数据库已回滚，但原实现仍返回前面的事项/处置列表；原实现还在事务回调内设置 `success=true`，提交失败会留下成功标志。改为在事务内部暂存结果，只有 `$transaction` 完成提交才发布结果。新增实际 SQLite 延迟外键与触发器，在 COMMIT 阶段拒绝事务，验证失败标志、空结果和数据库回滚。

本轮实际查询日志确认当前 Prisma 5.22 的 SQLite 交互事务使用 `BEGIN IMMEDIATE`。单 Prisma 实例的八次新建、跨进程普通新建、重复确认和同一来件手动兜底均未复现重复写入；这些路径已有数据库串行保护，不据理论推测重写其业务规则。它们已纳入回归。当前测试不等于高并发容量或生产负载认证。

## 后续：全仓构建与旧版 CI 阻断修复

用户随后明确授权修复两处类型错误、提交、推送并核验远程 CI。以上“构建失败/未推送”是第一阶段记录，后续结果如下。

- `evaluation/budget.ts`：用 `Object.defineProperty` 装饰原 Response 的 json 方法，避免直接赋给 Node 声明为 readonly 的属性；保持对象身份、响应元数据、原始正文与 AbortSignal。测试确认无预读/clone、仅成功读取一次后计 Token，重复读取失败不重复审计。
- `src/openai-compatible.ts`：把网络 JSON 视为 unknown，逐层检查 choices 数组、首条 message 与 content，再执行原有字符串与业务 Zod 校验。新增 7 种错误响应结构测试。未增加 DOM 全局类型、忽略错误或用类型断言跳过输入检查。
- 旧 CI `34013677359`（2026-09-06、提交 `0863862`）实际在 Business invariant tests 失败：98/99，其中八个同 key 文字保存请求出现 P1008 与交互事务过期 P2028。文字只写一条 Intake，改为直接原子 INSERT；保留唯一约束错误的幂等读取与载荷冲突 409。图片仍需 Intake/Attachment 同事务写入。本轮新增四进程同 key 回归，原有八请求不变量保留。没有提高超时或跳过断言。

本地后续验收：单测 **244/244**（25 / 33 / 82 / 104），业务不变量 **99/99**，四进程并发 **12/12**，Playwright **32/32**，typecheck 与**全仓 build 通过**。远程 CI 核验以推送后的完整提交 SHA 为准，不以旧版失败记录或本地成功代替远程结果。CI 只有检查步骤，本轮没有网站发布操作。

结构影响：AI 传输响应读取与评估审计包装的小范围修复；来件 API 仅调整文字单写入的事务边界；Domain、UI、模型配置与依赖未改。提交范围包含第一阶段并发修复及本次必要的构建/旧 CI 故障修复，不包含工作区原有调研或架构文档。
