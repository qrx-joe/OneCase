# OneCase 评委问答预案（结论先行版）

适用：现场展示的 2 分钟评委问答 + 另计 3 分钟评分期间的可能追问。依据《展示要求》：**答案优先给结论，再补充证据、数据或下一步计划**；由最熟悉问题的人（本项目即参赛者本人）直接回应。

## 0. 应答策略

- **结构**：第一句结论（是/否/数字/现状）→ 一层证据 → 边界或下一步。单答 30–45 秒，追问才展开。
- **听完整再答**；问题含糊先复述确认（"您问的是 X 还是 Y？"）。
- **不知道就承认**："这个我现在没有数据，不猜。我会用……把它弄清楚。"——比硬答更加分。
- **不争辩假设**：评委对场景的质疑（"社区根本不会这样用"）一律接回对照实验："这正是我第一步要验证的，方法在下一页。"
- **数字纪律**：只报 2026-09-06 实测口径（213 单测 / 99 不变量 / 32 E2E / 评估 24/26；PPT P9 提交版快照为 200，追问时说明材料定格后代码仍在演进）；准确率、提效、客户数——零。
- **超时信号**：工作人员提示后，当前问题一句话收尾，不再开新话题。

以下每题按【结论】【证据/数据】【边界/下一步】三段组织，现场只讲前两段，第三段视追问使用。

## 1. 必答题（最可能被问）

### Q1 AI 到底做了什么？人做什么？

- **结论**：AI 只生成结构化草稿和相似候选；创建、关联、状态变更全部由人触发。
- **证据**：Review 页草稿带"AI 草稿 · 未写入事项"标识；确认动作是人工点击，写入为原子事务；AI 原值与人工修改值都留审计。
- **边界**：AI 也可以完全不参与——手动创建事项的路径一直在。

### Q2 会不会把不同的事错关联到一起？

- **结论**：系统不自动合并；候选给到 Top3 并附匹配依据，最终由人核对——错误仍可能发生，所以人工闸门不能省。
- **证据**：楼栋/单元号归一化后对比，数字不同明确标注"位置不同"（Demo 中 CASE-011 即硬负例）；重复提交确认会被幂等拒绝。
- **下一步**：查重当前是标题/地点/类别/时间启发式，Embedding 语义检索在后续评估清单里。

### Q3 AI 挂了怎么办？

- **结论**：原始反馈保留，可重试、可转手动创建；默认不静默降级。
- **证据**：失败路径有代码与测试覆盖；只有 Demo 双开关同时开启才允许退回 Mock，且审计会如实记录 mock。
- **现场**：如果演示中真的失败，就地演示手动兜底——这是设计内场景，不是事故。

### Q4 图片/文字识别准确率多少？

- **结论**：尚未验收，我不给数字。
- **证据**：已做 30 次真实调用（20 文字 + 10 合成图片）的独立评估：加固后自动字段检查 24/26，漏项 0、多余 0；发现的问题（含一次提示注入）已做一轮缓解并复跑通过。
- **边界**：样本是我编写的合成标注、未经社区工作人员审核，不构成准确率结论；验收线要和场景方一起定。

### Q5 有客户吗？能提效多少？

- **结论**：还没有客户，也没有实测的提效数字——当前是 MVP。
- **下一步**：用同一批授权脱敏的真实反馈做对照实验：中位耗时、漏项、误关联、单次成本，验收阈值与场景方事先商定。
- **纪律**：不把"没有找到证据"说成"确认没有"，只说"目前没有可展示的"。

### Q6 一个人怎么落地？社区项目不是一个人能干的。

- **结论**：产品和工程我一个人能交付；流程梳理、安全合规、采购运维本来就要场景方和资源方参与——这在我的落地路径里，不是被问题问出来才想的。
- **证据**：试点前缺口清单（认证、权限、组织隔离、生产存储、PostgreSQL）已公开列出；商业路径第一步是"场景共建"。

### Q7 数据安全怎么做？居民隐私怎么办？

- **结论**：演示只用合成数据，页面明确标注 Demo；生产化之前，认证授权、组织隔离、数据脱敏是硬性前置项，没补完不接真实居民数据。
- **证据**：已知限制清单公开可查；图片当前存 SQLite（data URL），生产存储方案在试点前清单里。

### Q8 收费模式？

- **结论**：设想是"部署配置费 + 持续运维费"，付费方是社区服务运营主体——目前未验证，没有价格、合同或收入。
- **下一步**：先共建验证价值，再谈收费；谁有预算、谁采购，需要逐项确认。

## 2. 产品与技术深挖

### Q9 和现有的网格化平台 / 政务工单系统什么区别？

- **结论**：我不针对某个具体系统做对比；OneCase 的定位差异在"进台账之前的整理环节"——拆分、查重、人工确认、来源留痕，且 AI 建议与业务事实严格分离。
- **边界**：与存量系统是补充还是重复，需要对着具体系统看；如果场景方已有等效功能，对照实验会揭示它。

### Q10 查重为什么不用向量 / Embedding？

- **结论**：当前用标题词汇 + 地点 + 类别 + 时间的启发式排序，够 MVP 验证流程；Embedding 在清单里，但要等真实样本证明需要它、且值得它的成本。
- **证据**：候选带依据 + 硬负例标注，误判风险由人工闸门兜住。

### Q11 提示注入怎么防？（若评委懂技术）

- **结论**：不能声称具备注入防护。评估中确实发现过模型跟随恶意地点指令的问题，已做一轮提示词加固并在复跑中通过，另 3 个变体未被劫持。
- **边界**：这只是 4 个样本上的验证，不是普遍证明；架构上的根本兜底是——草稿字段人工确认，AI 写不进业务事实。

### Q12 为什么用 SQLite？生产怎么办？

- **结论**：参赛阶段刻意不迁移（已有决策记录 ADR-003）——先把流程验证做对，PostgreSQL 在试点前置清单里。

### Q13 并发场景：两个人同时确认怎么办？

- **结论**：确认接口幂等（重复提交被拒），状态变更带乐观锁（version 冲突即拒绝）。
- **边界**：已知限制如实报——Case 编号用 count()+1，高并发下可重号，已在清单里留作专项修复。

### Q14 AI 辅助开发的边界？原创性怎么界定？

- **结论**：OneCase 由我独立开发；AI 编程工具辅助写代码和测试，需求、方案、最终检查由我负责。开源组件（Next.js/React/Zod MIT、Prisma Apache-2.0、Lucide ISC）均注明来源，不把第三方算作原创。
- **证据**：27 个直接依赖 License 扫描记录在案（MIT 21 / Apache-2.0 5 / ISC 1）。

### Q15 为什么相信这些测试不是"自测自嗨"？

- **结论**：测试分四层且独立运行：纯业务规则（domain，无框架依赖）、契约（contracts）、AI 适配（含超时/重试/契约）、Web 服务层；另有 99 项业务不变量在独立临时库上验证；CI 每次提交全量复跑，本地与 CI 同一条流水线。
- **边界**：测试证明"按规格执行"，不证明规格本身正确——规格要靠场景验证。

### Q16 演示是提前写死的数据吗？

- **结论**：数据库是预置的合成 seed（6 事项/8 来件），但刚才那条分析是**现场真实调用模型**的输出，不是我提前塞好的。
- **证据**：可当场看审计记录里的 provider、模型版本与耗时。

## 3. 落地与商业追问

### Q17 你的目标社区从哪里来？

- **结论**：这正是本次参赛的目标之一——通过比赛对接愿意共建的场景方；同时个人渠道在接触社区服务运营方。
- **纪律**：不虚构"正在洽谈"，只说"在寻找、希望借助赛事对接"。

### Q18 如果对照实验证明没省时间呢？

- **结论**：那就如实接受，调整方向或停止投入——验收标准事先商定的意义就在这里。
- **加分点**：这个项目的设计初衷就是"数据决定继续与否"，不是先做产品再找理由。

### Q19 微信接入、语音什么时候有？

- **结论**：微信是后续评估项（当前入口未做）；语音入口已禁用，可自行转写后粘贴文字。时间表取决于试点场景的真实入口需求，不预先承诺。

### Q20 你最担心这个项目什么？

- **结论**（诚实版）：担心"整理"这个环节在真实工作流里没有想象中痛——所以对照实验是第一优先级；其次是单人维护的安全短板——所以试点前清单把认证与隔离排最前。

## 4. 新增功能追问（2026-09-06 加入演示后的可能问题）

### Q21 演示这个登录，就这么个固定账号密码？安全性呢？

- **结论**：这是**演示虚拟登录**——固定账号密码、只写浏览器本机会话，后端没有任何鉴权。它解决的是"演示完整性"，不是安全。
- **证据**：设置页里如实标注"演示环境"；登录页页脚写明演示凭据；试点前清单第一条就是真实认证与权限。
- **边界**：在它补齐之前，系统不接任何真实居民数据——这和"数据安全"的答案是一条线。

### Q22 设置页里一堆"敬请期待"，是摆设吗？

- **结论**：没有一个是假开关。真实生效的：通知偏好（真的控制顶栏铃铛提醒什么，有测试覆盖）、账号资料（读真实登录会话）、AI 识别配置（如实显示当前 Provider 与模型，Mock 环境就标 Mock）。
- **证据**：分类字典、退出登录也都是真的；没实现的能力统一标"敬请期待"并列在路线图，不在 UI 里冒充可用。
- **下一步**：这版设计的口径就是"有持久化、真实生效才给开关"，后续设置项照此原则加。

| 情形 | 话术 |

| 被问到完全没有数据的问题 | "这个我现在没有实测数据，不猜。已有的最接近的证据是……；补齐它的方法是……，已在我的验证计划里。" |
| 被指出演示/产品缺陷 | "您说得对，这一条在已知限制清单里（或：我记下来，回去核实）。它不影响/确实影响 X，我的处置是 Y。" |
| 被追问承诺 | "我只承诺已经验证的和计划验证的，时间表等试点方案定了再给。" |
| 完全答不上 | "这个问题我需要查证后回答，现场不编造。" |
