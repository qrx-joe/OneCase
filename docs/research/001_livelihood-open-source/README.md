# 民生服务开源项目参考地图

调研日期：2026-10-09。已按用户指定的 aias-meta-research 技能完成公开检索、源码抽查、差距分析与取舍草稿。用途：没有实际经办人员时，先用可追查的外部积累完善设计依据。

**建议：产品结构先学 CHILL，转介规则重点学 Primero；在 OneCase 现有技术栈上做最小闭环。** 中文 CaseBridge 是近似领域参考，但本轮未找到明确许可证，不能默认搬代码。该建议是静态研究判断，尚无本地经办人反馈或收益数据。

## 最值得看的项目

| 项目及源头 | 对应方向 | 本轮核实/边界 | 对 OneCase 的用法 |
|---|---|---|---|
| [CHILL（GitLab）](https://gitlab.com/Chill-Projet/chill-bundles) | 社工持续服务 | 对象关联多条服务路径、活动与负责人员历史；官方列有法国地方机构使用，未独立审计效果 | 首选产品结构参考；研究待办、服务路径和活动分层 |
| [Primero（GitHub）](https://github.com/primeroIMS/primero) | 弱势群体个案管理 | 源码区分内部转介接收、拒绝、完成，并检查同意与权限；外部转介仍需人工沟通 | 首选转介规则参考；只借鉴与当前需求有关的机制 |
| [CiviCRM / CiviCase](https://github.com/civicrm/civicrm-core) | 个案活动与时间线 | 个案、联系人、角色、活动时间线可追踪；不能据活动名称判定跨机构接单 | 备选结构参考；学习活动类型与计划时间线 |
| [OpenSPP2](https://github.com/OpenSPP/OpenSPP2) | 社会保护、个人/家庭服务 | 个案、探访、笔记、干预、转介有模型；内部手工改状态不等于外部回执 | 学记录拆分和家庭桥接；当前不迁移到 Odoo |
| [CommCareHQ](https://github.com/dimagi/commcare-hq) | 移动采集与持续跟进 | 表单更新个案；转介需按当前配置方法设计；旧 referral XML 已被现行 SQL 路径拒绝 | 学采集与跟进关系；不照搬旧接口示例 |
| [CaseBridge 案桥](https://github.com/selinyi123/casebridge) | 中文社工个案、计划、介入 | 持久化模型/路由已核验；转介由内部社工手工登记；许可证与真实部署未确认 | 中文领域参考，先读模型和人工确认边界 |
| [Open Referral HSDS](https://github.com/openreferral/specification) | 服务资源目录标准 | 机构、服务、地点、联系人、申请条件；规范明确排除个案转介跟进 | 将来资源卡的字段参考；不是个案应用 |
| [Bayes Platform](https://github.com/bayesimpact/bayes-platform) | 公共服务与就业 AI 助手 | 官网描述法国就业服务接入，仓库 MIT；本轮只查定位/许可，未核验就业流程实现 | 邻近 AI 参考，暂不排在手工服务闭环之前 |

补充检索了 [KinEcho（Gitee）](https://gitee.com/luobo_lin/KinEcho) 和 [SmartSeniorHMOS（GitCode）](https://gitcode.com/CAPTAIN1275/SmartSeniorHMOS)：前者偏家属日程/告警，后者公开版明确是假数据且本轮源码访问受限，均不能视为已验证的社工转介系统。GitLab 的 CHILL 已核验；Gitea 镜像是同一项目，不重复计数。Codeberg 被 robots.txt 阻挡。

## 对下一步的具体建议

扩大到民生服务时，可以用“服务对象—独立需求—多次活动—后续行动”连接就业、养老等场景。[世界银行 Case Compass 框架](https://case-compass.org/Home/Guide/CaseCompassFramework)同时覆盖老年人、失业者等群体，并区分信息指引、转介与专业个案工作。本轮建议先验证工作人员的持续跟进与转介协同；是否进入更完整的专业评估/介入，仍待职责与使用证据。该框架是公开参考资料，不是开源软件。

先设计“今天该跟进谁”的工作视图，再考虑更大的对象档案和资源平台。当前代码已有负责人、行动、时间、转介/结果状态与回访日期，但服务页逐项列出记录，没有按到期行动组织工作。

可审查的最小范围是：按有效联系日期显示待办，分出转介待接收、退回待补充、失联待联系；点开可看到负责人员、下一动作及合成证据。仍由内部人员人工登记外部反馈。产品优先级和字段取舍留在 [取舍卡](./decision.md)，本轮没有实施。

建议用失业者的岗位转介、老人的周期探访和助餐首次送达这三条合成链路检验同一个机制，避免按人群堆三个互不关联的系统。能演示流程不代表当地经办人愿意使用，也不能推导找到工作或服务质量改善。

## 执行与验证

1. 明确约束并核对自有实现 → verify：阅读服务模型、服务页、设计与走查材料，区分已有功能和假设。
2. 先抽查 Primero，再按同一判据并行取材 → verify：对核心候选追到模型与调用入口、检查许可、记录固定提交；只读取文件，不克隆或运行外部代码。
3. 汇总与反证复核 → verify：检查取舍卡能否说明选什么、舍什么、何处需用户决策；检查文档链接和当前改动范围。

限制：多平台检索有明确停止线，不宣称穷尽全网。未运行候选应用或测试；未独立验证机构使用与业务效果；没有真实经办人参与，本地需求验证尚未完成。
