# 核验任务与复核记录

日期：2026-10-09。采用用户指定技能的统一问卷。先完成一个候选的抽查，再开展并行核验；取舍仍由主任务汇总，产品方向留给用户。

## 统一问卷

1. 对象与持续活动：原生关联受助者/家庭、计划、多次活动、日期及历史吗？
2. 转介责任和结果：接收者是否具体？谁能发出、接收、拒绝、完成？外部反馈与内部手工登记是否区分？
3. 公开证据：源码、许可、固定提交、官方实施资料能否追查？维护者声明与独立使用/效果证据是否区分？

证据格式：原生/部分/明确不在范围/未核验 + 固定提交 + 文件:行号 + 原始链接 + 一句说明。至少沿一个模型到调用入口追踪；不能凭同名文件或关键词判断。缺少证据写未核验，不推定功能不存在。

每路核心结论上限 1000 汉字，证据清单另附。判断限定直接用/在其基础改造/只借鉴架构/不适合，并给首选、备选和三个风险。外部源码只读，不复制进业务代码。

## 主动找到的反证

- Primero 的内部分配/接收能力不能自动覆盖不使用该系统的机构。
- CHILL 官方 FAQ 明确没有无账号外部人员的访问，且完整逐人动作日志尚缺；服务路径完善不等于全功能审计或外部闭环。
- OpenSPP 转介接收/完成按钮由内部人员改状态，不等于提供方认证回执。
- CommCareHQ 当前 SQL 路径拒绝旧 referral XML；当前“转介”文档指配置方法。
- CaseBridge 对中文服务领域很接近，但当前核查未找到明确许可；不把公开可读等同可复用代码。

## 独立复核

完成取舍卡后，使用不继承任务历史的不同模型独立会话，只提供 decision.md，检查事实、推理和证据边界，并回答“选了什么、舍了什么、哪里需要用户拍板”。

结果：三项均答齐；未发现 P0/P1。一项 P2 指出“证明机制”可能超出静态证据，已改成“静态确认源码实现了这些状态转换；本轮未运行验证”。复核抽查了 Primero 固定源码和官方实施说明；没有代替用户填产品决策，也没有做运行或跨厂商验证。

OpenCode 本机可运行，但本轮可用模型清单未列出 StepFun；没有为跨厂商复核新增配置、凭据或付费调用。独立会话复核的覆盖不等于跨厂商交叉审查。
