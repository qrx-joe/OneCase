# 试点授权边界备忘（S0-T5）

- **性质**: 口头确认的备忘，不是协议。阶段 3 正式授权前有效。
- **对象**: 候选试点社区的负责人或可拍板人。
- **填写**: 每题尽量落到"能/不能/要请示谁"；"要请示"也算有效结论——它告诉你真正的授权链。

## 备忘表

| # | 问题 | 对方答复 | 跟进 |
|---|---|---|---|
| 1 | 如果试点，系统部署在哪？（社区电脑 / 街道服务器 / 云端 / 要请示信息办） | | |
| 2 | 谁能拍板数据使用授权？（职务 + 流程） | | |
| 3 | 居民数据能否发送给外部 AI 服务商？（能 / 不能 / 私有化部署才谈） | | |
| 4 | 有没有单位明文的数据红线（文件名/规定名）？ | | |
| 5 | 图片、语音这类附件怎么处理？（不留存 / 留存多久 / 没想过） | | |
| 6 | 试点期间出问题（数据错了、泄露了），责任怎么认定？ | | |
| 7 | 上级/街道有没有在建或在建成的类似系统？（避免"第四本账"的直接证据） | | |
| 8 | 试点愿意投入什么？（1-2 名社工用 2 周？只允许合成数据演示？） | | |

## 落盘

- 结论写入本文档 + `stage0-conclusion.md` 的"授权边界"节。
- 第 3、4、6 题的答案直接决定阶段 3（合规门票）的工作量与可行性；若第 3 题为"不能"，阶段 4 的模型选型必须按私有化/本地化重新评估。
