# Gate 1 可用性测试方案（S1-T7）

- **目的**: 回答"社工能否用手机独立完成关键任务，且不比现有方式慢、不错"。这是执行方案定义的 Gate 1 判定测试。
- **对象**: 3-5 位一线社区工作人员（与阶段 0 访谈对象可重叠）。每人 40-55 分钟。
- **材料**: [任务卡](./task-cards.md) × 8、[消息库](./messages-bank.md)、[记录表](./record-sheet.md)、配图 `tmp/usability-assets/`。
- **前置**: 建议在阶段 0 至少完成 1-2 人访谈后再测（知道他们的现行方式才能对比）；至少做过一次完整彩排。

## 一、环境准备（测试前一天完成）

1. `pnpm --filter @onecase/db db:push && db:seed`，然后 `pnpm --filter @onecase/web dev`（默认 3000 端口、mock Provider，离线可跑）。
2. 确认演示库状态：CASE-018（3栋2单元楼道照明故障）与 CASE-011（3栋1单元一层照明故障）存在——任务 2/4 的候选与 Hard Negative 依赖它们。**每位参与者开始前执行 `db:reset`**（清空业务数据并重新 seed，仅限演示库），保证候选池一致。
3. 设备（按优先级）：
   - **真机**：手机连同一 Wi-Fi，访问 `http://<电脑局域网IP>:3000`。真机若发现适配问题，**记录为测试发现**而不是测试失败——这正是要验证的（README 明示真机未验证）。
   - 备选：平板或桌面浏览器 + 窗口缩到手机宽度。备注实际用了哪种设备。
4. 录屏：桌面用系统录屏；真机用另一台手机支架拍摄 + 电脑端同时录屏兜底。**开始前口头确认拍摄许可**（同意书已含勾选项）。
5. 彩排：自己按全部任务卡走一遍并计时，剔除卡壳的表述。

## 二、流程（每人 40-55 分钟）

| 时段 | 内容 |
|---|---|
| 0-5 min | 欢迎；过一遍同意书；说明"测的是系统不是您，怎么吐槽都行"；演示首页 1 分钟 |
| 5-12 min | 自由探索：让 TA 随便点点 3 个页面，观察第一眼从哪进 |
| 12-45 min | 任务 1-8 按序执行；每张任务卡读口播稿，发布后不再补充提示 |
| 45-52 min | 复述 + 问卷（记录表第二部分） |
| 52-55 min | 开放吐槽（录音），问"如果给您用两周，您最担心什么" |

**提示规则（关键）**: 参与者求助时，只重复任务卡原文，不给操作提示；同一任务卡壳超过 5 分钟或明确放弃，记录后跳下一任务。任务间的"提示次数"是 Gate 1 数据。

**对照组设计**: 任务 1 和任务 4 各做两遍——第一遍"用您平时的方式把这条信息登记下来"（口头+纸质模拟，计时），第二遍用 OneCase。其余任务只测 OneCase，但结束时问一句"这个用您平时的方式大概要多久"。

## 三、计时口径

- 起点：任务卡读完（含消息展示）；
- 终点：任务卡定义的成功状态达成（如"确认完成，页面显示创建成功"）；
- 中途系统卡顿/等待 AI 的时间**照实计入**（真实使用就是如此），备注里标出等待占比；
- 用手机秒表 + 录屏回看校准。

## 四、Gate 1 判定标准（对齐执行方案 S1-T7）

3-5 人测试后汇总，全部满足才算通过：

| # | 指标 | 门槛 |
|---|---|---|
| G1 | 独立完成率 | 8 个任务中 ≥6 个"独立完成"（≤1 次澄清性求助） |
| G2 | 核心任务时间 | 任务 1/2/4 的中位用时 ≤ 该参与者自己的对照基线（任务 1/4 有两遍对比；任务 2 与口头估计比） |
| G3 | 严重错误 | 全场 0 次"错楼栋关联"（把 C3 的 3栋1单元 关联到任何 **3栋2单元** 的案——关联 CASE-011 或新建均正确）；漏拆事项 ≤1 次 |
| G4 | 流程复述 | ≥4/5 人能正确说出"系统帮我出草稿，我来决定建还是并、改了以我改的为准" |
| G5 | 主观意愿 | "愿意在试点中连续用两周"均分 ≥3.5（5 分制） |

**未通过的处理**: 只修归因指向的条目（哪题挂了修哪题），不加新功能，修完复测失败的任务；判定与归因写入结果文档。

## 五、结果落盘

1. 每人一份 [记录表](./record-sheet.md)；
2. 全部完成后写 `docs/testing/stage1-usability.md`：对比数据表、失败任务归因、与 Gate 1 五项判定的逐条对照、未验证项；
3. devlog 按 communicating 模板记录该轮；README「已知限制」中"真机未验证"一项按测试结果更新口径。

## 六、红线

- 全程只用合成材料与演示库；若参与者想"试试真的"，出示系统内"请勿录入真实居民隐私"提示并解释阶段 3 计划。
- 参与人编号 P1-P5；录屏与记录不出现姓名单位。
- 数据被玩坏只走 `db:reset`，绝不现场修库。
