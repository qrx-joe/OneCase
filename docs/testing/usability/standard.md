# 民生服务标准样本与验收约定

这是基于现有人工原型整理的候选标准，采用 `aias-meta-proto` 的定标方法。所有人物、机构、反馈与时间均为合成材料。用户尚未挑选或亲改样本，一线走查未执行；不能据此宣布定标完成、岗位帮扶有效或老人实际受益。

标准与原有[走查包](./livelihood-walkthrough-kit.md)放在一起，不改原参与者页。原型仍采用 Case 状态机，下面的结果状态只表示服务记录；脚本检查收尾条件，不执行事项状态迁移。

## 1. 第一眼需要看懂什么

工作人员应能从记录说明：服务属于谁、本人意愿是否确认、谁负责、下一步是什么、何时联系，以及本次结果有什么依据。字段存在可以检查；工作人员能否独立理解、是否多填一遍，仍需人核对。

参照物是[合成任务卡 L02、L05、L07、L10](./livelihood-scenario-cards.md)、[扩展方案 LS-02、LS-04、LS-06 至 LS-08、LS-11](../../product/livelihood-service-expansion.md)，以及当前 [service-record.ts](../../../apps/web/src/lib/service-record.ts)。原型能力以代码为准；开源研究提供结构参考，不补实际经办人证据。

## 2. S01：失业人员的白班岗位指导

对象 SYN-P01，负责人 SYN-W01。本人需要白班岗位指导，晚上照顾母亲。此样本的目标是完成本次岗位指导并核对限制，实际就业结果仍未知；失业登记、补贴资格另行核实。

| 步骤 | 合成事实与工作人员操作 | 期望记录 / 收尾条件 |
| --- | --- | --- |
| 初始 | 人工确认对象和本人意愿，约定 10 月 13 日 09:00 核对服务站进展 | 结果未知，有负责人和下一行动 |
| 转介发出 | 记录已向合成就业服务站发出，尚未收到接收反馈 | SENT / UNKNOWN，不能完成本次服务 |
| 转介接收 | 代记合成服务站已接收 | ACCEPTED / UNKNOWN，接收不代表已提供指导 |
| 指导提供 | 记录已核对白班限制并提供岗位指导 | PROVIDED，仍需反馈来源 |
| 结果确认 | 合成本人确认本次指导已完成；没有入职反馈 | CONFIRMED，可满足本次指导的收尾条件；不能写“已就业” |

转介、接收及反馈均为本地人工代记，不是外部机构回执。时间是样本安排，不是政策时限或真实预约。

## 3. S02：老人本次探访与下一周期

对象 SYN-P02，负责人 SYN-W02。人工核实对象与本人意愿，完成一次日常探访，并约定 10 月 17 日 09:00 再联系。助餐属于另一独立需求，不随探访完成而关闭。

| 步骤 | 合成事实与工作人员操作 | 期望记录 / 收尾条件 |
| --- | --- | --- |
| 初始 | 本人意愿已人工确认，本次直接服务，不转介 | NONE / UNKNOWN，不能提前收尾 |
| 本次探访 | 记录已探访及本次情况 | PROVIDED，尚不能确认结果 |
| 核对反馈 | 合成本人确认本次探访；填写后续联系时间 | CONFIRMED，有反馈依据和后续时间，满足本次收尾条件 |
| 新周期 | 关联已完成的合成旧事项 SYN-C-V01，重新确认本轮意愿与安排 | 保留对象编号和历史引用，意愿 UNKNOWN、结果 UNKNOWN、转介 NONE，旧结果不能继承 |

当前 UI 新周期保留对象核实标记并重置本人意愿；本样本与之对齐。脚本仅检查新记录初始化，不证明旧事项存在、已完成或关联写库成功；这些应用层约束由已有 API/E2E 覆盖。

## 4. 可执行检查与三层验证

两条样本的机器输入、逐步期望与八条负例统一放在 [fixtures](./livelihood-prototype-fixtures.json)。文字表用于人审，fixtures 用于复现。修改样本时须同步两者；脚本不能自动证明叙述和结构化输入语义相同。

v1 明确包含 S01、S02、N01 至 N08 和 S02 新周期，检查器会拒绝遗漏；变更覆盖范围时须有对应版本与材料修订，不能靠减少用例获得 PASS。

在仓库根目录运行（Windows）：

```powershell
pnpm.cmd --filter @onecase/web exec tsx ../../docs/testing/usability/check-prototype.mts
pnpm.cmd --filter @onecase/web exec vitest run src/lib/__tests__/service-record.test.ts
```

脚本调用现有业务规则，检查样本逐步结果、收尾条件、序列化恢复、新周期初始化和负例；任何断言失败即非零退出。不写数据库、不发转介、不调用模型，也不自动改变本文件的审批状态。已有回归测试负责具体规则，详见[负例与人工清单](./negatives.md)。

| 层次 | 本轮可验证 | 继续保留的未知 |
| --- | --- | --- |
| 规则 | 两条合成链路及八条负例与当前业务函数是否一致 | API 持久化、并发、浏览器操作不由本脚本覆盖 |
| 判据 | 对象、意愿、下一行动与结果边界是否清楚 | 用户偏好、材料易读性与需要删减的字段待人审 |
| 实效 | 本轮不生成参与者记录 | 经办人独立完成、现行职责、重复录入负担、服务成效均未验证 |
